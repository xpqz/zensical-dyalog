# How-to guides

A how-to guide is a recipe for a task you already know you need to do: what it assumes, the steps, and the result. It links to the reference for the detail rather than repeating it.

## Tools with their own guides

Several Dyalog tools are documented alongside their source, and their guides version with the tool rather than with the interpreter:

- [Link](https://dyalog.github.io/link/4.1): keep APL source in text files and work on it with any editor and version control.
- [RIDE](https://dyalog.github.io/ride/4.6/): the remote and cross-platform development environment.
- [HttpCommand](https://dyalog.github.io/HttpCommand/5.9): make HTTP requests from APL.

## What belongs here

A how-to guide is titled with what you will have done at the end ("Start APL from a script", "Create an executable"), says what it assumes, has numbered steps where order matters, and ends with a result you can check. Anything that teaches rather than instructs is a [tutorial](../tutorials/index.md); anything that describes rather than instructs is reference.
